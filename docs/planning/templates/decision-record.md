# Research or Implementation Decision Template

Create in `docs/decisions/` using the next available project ID when a decision is actually needed. Do not reserve fabricated approvals in advance.

## Identity

Decision ID/date/status; requesting task and branch; decision owner/reviewer role; affected documents, equations, requirements, experiments and claims.

## Concrete problem

What evidence triggered the choice, exact domain and observed limitation, source/run/uncertainty references, and why routine work cannot resolve the scientific choice.

## Options

| Option | Work/code/data required | Benefit for the scientific question | Cost/resource estimate | Effect on prior claims/results | Remaining uncertainty |
|---|---|---|---|---|---|
| Recommended bounded action | | | | | |
| Alternative | | | | | |
| Retain current limit / stop this branch | | | | | |

## Proposed choice

Evidence-based rationale, scope, preconditions, success/failure conditions, new task IDs and re-entry gate. State which changes are routine implementation versus a change to a scientific target, acceptance criterion, material/domain or baseline sequence.

## Actual decision

Decision-maker/date, accepted option, conditions and unresolved issues. Until an approval that is actually required exists, mark PROPOSED and continue independent authorized tasks. Never present the proposal as approval.

## Consequences

Version/archive changes; old runs retained; new experiment/configuration identity; required independent checks; board/traceability updates; next evidence needed to reconsider.
